1. Introduction

Marvel Trivia/Game is a browser-based trivia application where players choose a Marvel hero, select a difficulty level, answer timed questions, and compare results on a leaderboard. This report describes the system requirements, architecture, data model, interfaces, and validation strategy in a format inspired by IEEE Software Requirements Specification structure.

The application is implemented without front-end or back-end frameworks. It uses PHP pages for server-rendered views, SQLite for persistence, and vanilla JavaScript with Fetch/Ajax calls for quiz flow, score submission, leaderboard data, RSS integration, and browser notifications.

2. Overall Description

The system provides a small but complete trivia platform. Guests can browse heroes, switch language between Romanian and English, register, log in, and play quizzes. Authenticated users can save scores and appear in rankings. Administrators can maintain heroes and questions and import or export data in CSV and JSON formats.

Product context and major assumptions.
Aspect Description
Runtime PHP built-in server or compatible PHP web server, with SQLite support enabled.
Client Modern web browser with HTML, CSS, JavaScript, Fetch API, and optional Notifications API support.
Persistence Local SQLite database seeded through the project setup scripts.
Constraints No application frameworks; implementation relies on standard PHP, PDO, browser APIs, and static assets.

3. User Classes

3.1 Guest

A guest can view the homepage, inspect available heroes, switch language, register, log in, start a quiz, and view public leaderboard information. Guest quiz results are calculated, but persistence is reserved for authenticated accounts.

3.2 Authenticated User

An authenticated user can play quizzes by hero and difficulty, submit answers for server-side validation, save scores, view personal placement in the leaderboard, and log out.

3.3 Admin

An administrator has access to the admin panel, where questions can be added, edited, and deleted; heroes can be edited; and question or hero data can be imported and exported using CSV or JSON.

4. External Interface Requirements

4.1 User Interface

The user interface consists of PHP-rendered pages in the public directory. Main pages include the homepage, quiz page, leaderboard, authentication pages, and admin screens. The interface supports responsive layouts, bilingual labels, hero imagery, form controls, score tables, and quiz interaction states.

4.2 Software Interfaces

The PHP application communicates with SQLite through PDO. Browser JavaScript communicates with JSON and RSS endpoints under public/api. Data import/export supports JSON and CSV representations for administrative maintenance.

4.3 Communications Interfaces

HTTP is used for page requests, form submissions, Fetch API requests, RSS feed retrieval, and static asset delivery. Browser notifications depend on user permission and browser support.

5. System Features

Functional requirements grouped by feature.
Feature Requirement Primary users
Hero homepage Display hero cards with localized descriptions and links to start hero-specific quizzes. Guest, Authenticated User
Language switch Allow Romanian and English interface text, preserving the current context where possible. All users
Authentication Support registration, login, logout, session-backed identity, and role-aware navigation. Guest, Authenticated User, Admin
Quiz play Load randomized questions by hero and difficulty, present answer options, track time, and submit answers. Guest, Authenticated User
Server-side validation Grade submitted answers on the server using session-held correct answers rather than trusting the client. Guest, Authenticated User
Score saving Persist score, difficulty, hero, answer count, and time for authenticated users. Authenticated User
Leaderboard Aggregate scores by player, filter by hero and difficulty, show recent matches, and expose JSON/RSS data. All users
Notifications Use browser notifications for leaderboard-related updates when permission is granted. All users
Administration Allow admins to manage questions, edit heroes, and import/export data as CSV or JSON. Admin

6. Nonfunctional Requirements

6.1 Security

  • Database access shall use prepared statements through PDO to reduce SQL Injection risk.
  • Dynamic output shall be escaped with htmlspecialchars or XML-appropriate escaping where applicable.
  • Admin functionality shall be protected by an administrator role check.
  • Quiz scoring shall validate answers server-side and avoid exposing correct answers during play.

6.2 Reliability

The application should return structured JSON errors for API failures and valid RSS output for feed consumers. Database setup scripts should be repeatable for local development.

6.3 Usability

The interface should be understandable for casual players, support both Romanian and English, and provide clear quiz, score, and leaderboard feedback.

6.4 Maintainability

The codebase should remain framework-free and organized by pages, reusable includes, API endpoints, database scripts, static assets, and admin modules.

7. Architecture

The system follows a simple server-rendered PHP architecture. Pages render initial HTML, and JavaScript uses Fetch to call API endpoints for dynamic quiz and leaderboard interactions. 8. Data Model

Primary persistent entities.
Table Purpose Important fields Relationships
users Stores registered accounts and roles. id, username, email, password_hash, role, created_at Referenced by scores.user_id.
heroes Stores playable hero metadata and image paths. id, name, description, description_ro, image_url Referenced by questions.hero_id and scores.hero_id.
questions Stores quiz questions, localized text, options, correct answer, and difficulty. hero_id, question_text, option_a to option_d, correct_option, difficulty Belongs to a hero; deleted when the related hero is deleted.
scores Stores completed quiz results for authenticated users. user_id, hero_id, difficulty, score, total_questions, correct_count, time_taken, played_at Belongs to a user and a hero; supports leaderboard aggregation.

9. API Endpoints

Fetch/Ajax and feed endpoints exposed under public/api.
Endpoint Method Inputs Output Responsibility
/api/question.php GET hero_id, difficulty JSON quiz payload without correct answers. Loads randomized questions, localizes content, shuffles options, and stores correct answers in session.
/api/submit.php POST JSON body with answers and time_taken. JSON score, correctness breakdown, save status, and result metadata. Validates answers server-side, calculates score and bonuses, and saves authenticated results.
/api/leaderboard.php GET Optional hero_id, difficulty, limit. JSON leaderboard rows. Aggregates player scores and supports filtered leaderboard views.
/api/rss.php GET Optional hero_id, difficulty, limit. RSS 2.0 XML feed. Publishes leaderboard ranking as a feed for external readers.

10. Development Stages

  1. Define project scope, user roles, core trivia flow, and database schema.
  2. Implement public pages, shared includes, styling, and hero browsing.
  3. Add authentication, role-based navigation, and session handling.
  4. Build quiz APIs for question loading and server-side answer submission.
  5. Add score persistence, leaderboard aggregation, recent matches, and RSS feed output.
  6. Implement bilingual Romanian/English text and translation seeding.
  7. Build admin CRUD workflows and CSV/JSON import/export tools.
  8. Validate HTML, PHP syntax, API behavior, database setup scripts, and browser interactions.

11. Testing and Validation

Testing should combine manual browser scenarios, PHP syntax checks, database setup verification, API response checks, and W3C HTML validation. Key validation scenarios include:

  • Fresh setup creates all required tables and seed data.
  • Homepage hero images load and localized text switches between Romanian and English.
  • Registration, login, logout, and admin authorization behave as expected.
  • Quiz questions load by hero and difficulty, answer order is shuffled, and correct answers are not exposed.
  • Quiz submission returns a score and saves it only for authenticated users.
  • Leaderboard filters, recent matches, RSS feed, and notification permission flow work in supported browsers.
  • Admin question CRUD and hero editing preserve data integrity.
  • CSV/JSON import/export handles valid input and rejects malformed or incomplete data.

Suggested command-line checks include php -l on edited PHP files and manual calls to each API endpoint after running the setup scripts.

13. Appendix: Setup Commands and Demo Script

A fresh local installation can be prepared with the following commands from the project root: 

php database/setup.php
php database/seed_translations.php
php database/seed_demo.php
php -S localhost:8000 -t public

The script database/seed_demo.php is optional. It inserts demo leaderboard data so rankings and the RSS feed can be tested without manually playing many quiz sessions.

The required demonstrative video is separate from this script: it is a 3-5 minute video presentation prepared by the team to show the application features and implementation.
